## Approved design

| ADR  | Decision                | Choice                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0001 | Distribution            | Own unlocked package, no namespace, on A `1.1.0-1`. Logs through `ILogger` and alerts through `IAlertSink`; never depends on B                                                                                                                                                                                                                                                                                                   |
| 0002 | Message store           | Custom object `Inbound_Message__c`. Status `Received → Processed`, or `Failed` and then `Dead`. Fields: `Idempotency_Key__c`, `Message_Type__c`, `Source__c`, `External_Message_Id__c`, `Payload__c`, `Payload_Ref__c`, `Status__c`, `Attempts__c`, `Next_Attempt_At__c`, `Last_Error__c`, `Correlation_Id__c`, `Occurred_At__c`, `Processed_At__c`                                                                              |
| 0003 | Idempotency key         | The producer's key, `Source__c + ':' + External_Message_Id__c`, in a unique, case-sensitive external Id. Insert with `allOrNone=false` through `IPartialDml` (user mode); `DUPLICATE_VALUE` means already received, including repeats within one batch (no in-memory dedupe, changed 2026-11-15). No key means rejected; no Create access throws `MessageStoreException`                                                         |
| 0004 | Dispatch                | Bulk Command `IMessageHandler.handle(List<InboundMessage>)` returning one `HandlerResult` per message (success, retryable, fatal). `Message_Route__mdt` maps a type to handler classes (`Type.forName`). More than one route becomes a `CompositeMessageHandler`; the worst result wins                                                                                                                                          |
| 0005 | Ordering                | No ordering guarantee. Handlers guard against stale updates with `Occurred_At__c`                                                                                                                                                                                                                                                                                                                                                |
| 0006 | Finalizer recovery      | `MessageProcessorJob` claims a batch with a `FOR UPDATE` row lock (the lock is the claim; no stored in-flight status), dispatches and records outcomes in one transaction. `MessageProcessorFinalizer` recovers a failed job's messages (`Failed` with exponential backoff, or `Dead` at the maximum), alerts, and always decides the next run. One duplicate signature keeps one job queued. Limits in `Ingestion_Setting__mdt` |
| 0007 | Intake                  | High-volume Platform Event `Inbound_Message_Event__e` (Publish After Commit) with a trigger domain, `RetryableException` on every failure and resume checkpoints. The Automated Process user stores and processes everything with no permission set (probe 2). `PlatformEventSubscriberConfig` with `Event_Ingestion_Processor` is the documented alternative                                                                    |
| 0008 | Claim Check (built now) | A payload over the inline limit is uploaded by the producer as a `ContentVersion`. The event carries the claim (`Payload_Ref__c`), and `IPayloadResolver` loads it at dispatch, within a per-message size cap that fits the async heap                                                                                                                                                                                           |
| 0009 | Stall detection         | `StallSweeperSchedulable` on four 15-minute schedules (a documented setup step) runs `StallDetector`: reads due messages in user mode, publishes `Processor_Wake_Event__e` so the job runs as the Automated Process user, and alerts WARNING on messages due for more than `Stall_After_Minutes__c` (30). No locks to reset (ADR 0006)                                                                                           |

## Probes for the dev org, before spending CI orgs

1. **Proven 2026-11-13 in `aei-dev`:** an `allOrNone=false` insert (system or user mode) gives `DUPLICATE_VALUE` only to the repeated row. The first copy in a list succeeds and the rest of the batch is unaffected, so the in-memory dedupe is optional. A stored key also gives `DUPLICATE_VALUE`; the key is case-sensitive; `getFields()` is empty, so classify on the status code. Defaults: `Received`, attempts 0.
2. **Proven 2026-11-16 in `aei-dev` (the premise was wrong):** the Automated Process user needs **no** permission set. With none assigned, it passed `isCreateable()`, inserted in user mode, and its processor job claimed and updated messages, including one another user owned (OWD Private). `RetryableException` redelivers with `retries` counting up; a resume checkpoint after taking 2 of 5 events gave runs of 5, 3 and 1, all stored once. Tests with `Test.getEventBus().deliver()` behave the same way.
3. **Proven 2026-11-15 in `aei-dev`:** after a real `LimitException` the Finalizer keeps the claimed Ids, sees the job's DML rolled back, can do DML and enqueue one job (a second throws an uncatchable `LimitException`). A Finalizer-enqueued job starts again at depth 1; chaining from `execute` stops at depth 5 in Developer Edition. A 1-minute `AsyncOptions` delay ran about 60 s later. The duplicate signature (32 bytes at most) rejects a second enqueue only while the first is Queued; in a real org no row is created. In tests, `stopTest` rethrows a job's ordinary exception and the Finalizer runs, but the job's DML isn't rolled back, and any enqueue from a _successful_ job's Finalizer is an uncatchable `LimitException` (fine in a real org: three generations chained).
4. **Proven 2026-11-15:** a test can't force a `LimitException` (it ends the test). Tests use a fake `FinalizerContext`, a mocked dispatcher that throws, and a mocked `IProcessorQueue`.
5. **Proven 2026-11-15 in `aei-dev`:** apex-core-lib (installed 04t, no namespace) resolves C's unpackaged `public` `MessageStore` through one-argument `Type.forName`, the same path `MessageRouter` uses for `example/`. An unknown name returns `null`; names match case-insensitively; inner classes resolve. C running as a 04t itself is checked in PR 9's install smoke test.
   5b. **Proven 2026-11-15:** while a savepoint is active, every callout throws "All active Savepoints must be released before making callouts", even after a rollback. `Database.releaseSavepoint` lifts it, also after DML and a rollback. `HttpCalloutMock` enforces the same rule in tests.
6. **Proven 2026-11-15 in `aei-dev`:** three concurrent user-mode `FOR UPDATE` claims took turns and got 50, 30 and 0 of 80 rows, none twice. A waiter past 10 s gets a catchable `QueryException` ("Record Currently Unavailable"). `ORDER BY` with `FOR UPDATE` is rejected. A Processor user can claim but not update a message another user owns (`INSUFFICIENT_ACCESS_ON_CROSS_REFERENCE_ENTITY`).
7. **Proven 2026-11-16 in `aei-dev`:** the Automated Process user (trigger and Queueable) reads every `ContentVersion` and its `VersionData` in user mode, with or without a `ContentDocumentLink`, and can link a file it doesn't own. A user-mode `ContentDocument` query returns nothing unless the file is shared with the user directly. `VersionData` costs about its size in heap; `toString()` doubles it until the blob is released. `Limits.getLimitHeapSize()` reported 10,000,000 (trigger) and 25,000,000 (job); the design keeps to the documented 6/12 MB. A test showed `Blob.toString()` throws `StringException` on invalid UTF-8.
